# Adaptive operation timeouts — contract and remaining design

2026-10-30, Prompts 93–96. **AT-03 compatible-stream contract implemented; AT-05 supported Chat settings wired; calibrated defaults and additional dialects remain proposed.** This document distinguishes the implemented opt-in compatible-stream contract from remaining proposals. Existing default/Agent total deadlines, security limits, roadmap adoption and live acceptance are unchanged. [Engineering standard](ENGINEERING_STANDARD.md), [Agent Runtime](../concepts/AGENT_RUNTIME.md), [P4 policy design](../audits/P4_03_ADAPTIVE_RESOURCE_POLICY_DESIGN.md) and [P93 diagnostic result](../audits/P1_P2_TRANSPORT_DIAGNOSTICS_RESULT.md) supply context.

P94 implementation update: bounded classifier/planner parent budgets, changed-reserve re-admission and native/streaming result diagnostic parity are now implemented and fixture-verified; see the [result](../audits/P1_P2_AGENT_DEADLINE_AND_PROVIDER_PARITY_RESULT.md). Calibrated initial-response/useful-progress/idle defaults below remain a proposal, with local long-wait compatibility preserved.

## Prompt 95 implemented slice (AT-03)

`InferenceTimeout.h` owns the typed per-request options, effective policy and monotonic progress watch. `ChatRequestOptions.inferenceTimeout` reaches the existing SelectedEndpointChatProvider → LocalInferenceOptions → compatible streaming parser → ProviderRequestRuntime event loop. No second runtime, executor, router, persistent configuration or UI timer was introduced. See [P95 result](../audits/P1_P2_AT03_ADAPTIVE_INFERENCE_TIMEOUT_RESULT.md).

| Concept | Implemented semantics |
|---|---|
| Initial response | Explicit `initialResponseMs`, zero disabled. Starts immediately before POST, after admission/serialization. First observed HTTP metadata or validated visible text ends this wait. First response time is observation time, not upstream acceptance. Headers alone start the idle wait and cannot reset it repeatedly. |
| Useful-progress idle | Explicit `usefulProgressIdleMs`, zero disabled. Starts on initial response; if the initial timer is disabled, starts at dispatch. Only fully parsed non-whitespace `choices[0].delta.content` appended to visible output resets it. At the exact expiry boundary progress is rejected. |
| Total | Existing configured timeout and shared OperationDeadline remain absolute independent bounds. Timers, parsing, progress, startup status and child attempts cannot renew the parent. The timer is precise; monotonic checks also fence read/return paths. |
| Cancellation | Existing token wins over simultaneous timeout. Abort is local, polling at 25 ms while the event loop runs; scheduling/non-cooperative code and remote cancellation are not real-time guarantees. Late output cannot become successful completion. |

The first slice supports ordinary OpenAI-compatible visible-text streams for cloud, LM Studio and llama.cpp via the existing endpoint adapter. It does **not** stream structured classification or native tool-call assembly. Tool-call fragments, hidden reasoning, role/usage metadata, malformed/incomplete JSON, comments, whitespace-only text and arbitrary bytes do not count. Usage stays optional and is normalized independently. Completed transport is not sufficient: missing final completion, empty output, truncation, timeout, cancel or resource-limit failure never succeeds. Partial visible text may have been presented before a failure; no complete reply/tool call is manufactured and no stream retry is initiated.

New policy requests to Ollama, Claude/Gemini native streaming and non-streaming requests are explicitly rejected rather than ignored. Their existing zero/default or finite-total behavior remains compatible. Unknown progress support cannot enable a requested policy. An initial-only new profile without idle or finite configured/parent total is refused, preventing headers from leaving that profile hanging indefinitely. Both new fields zero retain legacy local zero-timeout compatibility, with Stop available. No new cloud 60/120 s budgets or hardware heuristics were adopted. Model/hardware calibration is unavailable and explicitly unused; missing telemetry implies no capacity claim.

Parser safety is independent of clocks: read in 64 KiB slices, cap one line/pending fragment at 1 MiB, total received stream at 8 MiB, visible UTF-8 output at 4 MiB and retained chunks at 4096. Limits are conservative memory/protocol ceilings, not measured token/hardware performance or a replacement for server output/context admission. They apply to this existing parser, including its native dialects; native adaptive timing is still unsupported. Limit breach aborts and fails without retry. Follow-up calibration must measure legitimate long-output streams before changing these bounds; progress cannot relax them.

Diagnostics retain only policy numbers, support/location/origin, response/progress timings/counts, bounded-parent fact/remainder, stable stop category and partial/resource-limit flags. They contain no text, prompts, URLs, headers, keys, reasoning or tool arguments. They travel in existing result diagnostics; this slice adds no schema migration or complete new durable Chat diagnostic store.

### Historical P95 settings proposal (superseded for the P96 supported Chat slice)

Extend the existing AppSettings/ISettingsStore and generated runtime/Desktop settings contract in one later migration. Preserve `localInferenceTimeoutMs=0` and every explicit provider total until the user opts into a reviewed profile. Add a versioned optional inference profile containing mode (legacy/standard/extended), integer-millisecond initial/idle values, finite total for extended mode, backend/operation capability applicability and provenance (user vs calibrated default). Reject negative/overflow values and unsupported profiles before dispatch. Extended mode requires an explicit finite safety total and normal resource/context admission; it cannot enlarge the cloud classifier parent implicitly. Choose defaults/maxima only after backend/hardware calibration, not in QML.

Resolve one immutable effective policy in ModelService/request ownership and project that snapshot to the existing QML-safe view model: effective initial/idle/total (or clearly labelled legacy disabled), backend support/fallback and Cancel. No second preferences file or per-widget constants. A model startup/readiness profile belongs to the model-operation owner, not an inference-progress reset. A requested new profile lacking reliable progress must explicitly fall back to an acknowledged finite total or be rejected; never invent progress.

Daemon disconnect ends the client's certainty, not daemon ownership. Preserve existing session/run/message IDs and generation fencing; reconnect queries state without replaying a mutation. A late request acknowledgement/completion is reconciled against that identity and cannot restart a task. Stop remains cancellable through the existing daemon command; client RPC timeout, approval timeout and worker join stay distinct. UI implementation acceptance must cover disconnect, late reply, cancel, loading/error/empty, keyboard/focus and responsive states before exposing settings.

## Prompt 96 implemented settings slice (AT-05)

The preceding settings proposal is now implemented for supported plain-text Chat in the existing settings owner: versioned `inferenceTimeoutProfile.v1` through SettingsService/AppSettings, ModelService resolution, the existing typed settings-service IPC and the real Desktop Models & Providers card. [P96 result](../audits/P1_P2_AT05_ADAPTIVE_TIMEOUT_SETTINGS_RESULT.md) records ownership, validation, migration, UI and first-failure/rerun receipts.

Compatibility preserves the historical Chat 120 s request and existing direct-local zero/configured preference; no migration turns local zero into a finite cap. Explicit Extended/Custom totals replace that Chat default by user choice, respect a shorter configured provider ceiling and never extend a finite parent. Initial/idle are capped by the resolved total. Explicit profiles own a parent before context admission; active request snapshots are immutable. Agent 60/120 s cloud parents, local Agent compatibility, approval/process/lease lifetimes and schema-8 history are separate.

No durations are guessed for Extended: the user chooses positive initial/idle/total. Custom allows disabled initial/idle with finite total. Unsupported/missing progress capability rejects the requirement at save and actual send; no silent fallback or invented metadata. A selected-model UI preview and actual captured workspace/model request use the same resolver. Save is Pending until the authoritative value is observed; disconnect/late ack causes inspection, not mutation replay. Older daemons missing the new rows show unavailability. Hardware calibration, native dialects, per-active-phase UI evidence and native platform acceptance remain deferred.

## Proposed policy and ownership

Keep policy in existing runtime/provider operation owners, with one resolved immutable effective budget per operation. Add typed options only when consumers and serialization need them; do not introduce another execution manager. Separate:

1. **Initial-response timeout:** start at admitted dispatch; wait for a documented observable response milestone. Qt request queueing/connect/TLS/request-sent observations are local phases, not proof of provider acceptance. An initial HTTP header can end the network-response wait but cannot satisfy semantic generation progress.
2. **No-useful-progress timeout:** after initial response, reset only on validated operation-specific progress: parsed nonempty visible generation output, a valid provider tool-call delta under bounded assembly, validated increasing download bytes, or an authoritative loader readiness milestone. Header churn, TCP keepalive, arbitrary SSE comments, CPU/GPU use and repeated identical heartbeats do not reset it. Count bytes/chunks separately for diagnosis, with parser/size limits.
3. **Total deadline:** monotonic parent operation deadline that no progress, retry, repair, redirect, cold-start event or nested child can extend. Compute child remaining time from that deadline. Keep retry count/output/memory/concurrency limits independently bounded.
4. **Cancellation:** explicit user token outranks timeout classification at the race boundary; bound polling/abort/drain and fence late generations. Cancellation is local unless a documented provider acknowledgement exists. A stopped UI is not a joined worker or proof of cancelled billing.
5. **Provider limits:** documented server TTL/quota/Retry-After and capabilities constrain policy; do not manufacture them from model names. Missing usage/capacity/progress is unknown. Fallback policy is conservative and inspectable.
6. **Cold start / slow hardware:** distinguish an owned model-start operation from inference. Permit an explicit longer bounded startup profile with measured memory/disk/ownership and cancellable readiness checks. Do not infer useful progress from utilization or extend a cloud request because the local GPU is busy.

### Proposed configuration contract

A future settings change exposes standard and extended operation profiles with separate finite initial/idle/total values, units, sensible validation and a visible effective operation summary. No universal numeric defaults are adopted here: calibrate against the existing ENV/BE/BUD matrix and real local/cloud profiles before replacing defaults. Fixed shipped defaults must remain finite; optional user-initiated long operations require an explicit finite extension, a maximum bound, resource admission and working Stop. An unavailable semantic-progress signal falls back to a finite total deadline rather than disabling waits.

Migration must preserve existing explicit local timeout preferences until a reviewed conversion is selected; the current zero default cannot silently become an arbitrary short cap. Conversely, zero cannot be carried forward as an unlimited default under a new policy without explicit compatibility treatment and user communication. Preserve current settings until that design is implemented. Settings/UI/API types have one owner; no per-widget timeout tables.

RPC acknowledgement, approval expiry, process timeout, model lease lifetime and inference lifetime stay independent typed concepts. A timed-out acknowledgement requires status reconciliation through existing run/session IDs, never blind mutation replay. Starting model unload/delete requires real ownership/quiescence; an Agent terminal state or idle Chat UI alone is insufficient.

## Decisions intentionally deferred

No larger global timeout, speculative reasoning parameter, classification bypass, adaptive permission relaxation or automatic retry expansion. No hardware utilization signal is promoted to semantic progress. The two retained Prompt 92 no-status timeouts alone cannot select a better budget or prove a remote root cause. Agent D/E remains incomplete until actual production tools execute and independent artifacts support accepted final claims.
